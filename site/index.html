Scoped, audited DNS changes, whatever the provider

DNS provider credentials open far more than one record. dns-gate holds them alone, for EuroDNS and Route53 today and more to come, lets pipelines, people and AI assistants in with short-lived identities, and lets each team change only the records it owns.

Why a gate

One provider key opens the whole account

EuroDNS is the extreme case: its API authenticates with two headers and no scope, and the key that adds a CNAME can also change the registrant contact, the nameservers or the renewal of every domain. With any provider, the credential a pipeline needs for one record reaches much more, and nothing says which team owns which record. A leaked key is a domain hijack, not just a DNS change.

Keys carry no scope

One key reaches domains, contacts, renewals.

The gate holds it alone; callers bring short-lived tokens scoped to zone, host and type.

10 requests per 10 s per IP

Progressive bans: one noisy client blocks everyone behind the same IP.

One shared budget for every client, writes serialized per zone.

Whole-zone saves only

The right to change a record is the right to wipe the zone.

Every changed record set is checked; a team only changes what it owns.

No ETag, no If-Match

Two concurrent writers silently overwrite each other.

Per-zone lock, zone version served as ETag, If-Match honoured.

How it works

One gate in front of your DNS providers

Clients use the gate REST API, the same for every provider, or keep the EuroDNS API they already speak: only the base URL and the credentials change. Every request, read or write, walks the same seven checks before anything reaches a provider.

Three layers

1

Provider account scope

The gate’s own credentials are limited at the provider, a restricted EuroDNS user or an IAM role scoped to the hosted zones: a last line if the gate itself is compromised.

2

RBAC

Who may read or write which zone, host pattern and record type. Protected records, such as the apex NS, SOA, MX and CAA, win over any role.

3

Ownership

Only record sets created or adopted through the gate, owned by one of the caller’s teams, and unchanged since the gate last wrote them.

Ownership

The gate only changes what it created

A DNS record has no free field to carry an owner, so custody lives in the gate’s store, per record set (zone, host, type) and per team, with a hash of its content. Every record set carries one of these seals, in the UI and in the API.

Held

Created or adopted through the gate. Its team may change it.

Pending

A write is in flight. The next reconcile settles it if the gate stopped midway.

Tainted

Changed or deleted outside the gate. Blocked until it is adopted again.

Foreign

Existed before the gate. Read-only through it until an operator adopts it.

Protected

Matches a protected rule. Refused for everyone, admins included.

Safe writes

Every write is checked against the zone as it is now

Adding, changing or deleting a record set is computed against the current zone, under a lock and with the expected content of each record set, so a client holding a stale copy cannot overwrite or wipe records it never saw. With EuroDNS, which has no record update endpoint, the write is one checked save of the whole zone:

4–5EuroDNS calls per write
~5 sper write at the shared rate, by design
1writer at a time per zone

Policy

Deny by default, then name who may change what

An issuer says which tokens to trust, a role says what may change, a binding gives a role to a group or a subject and names the team that will own what it writes.

issuers:
  - name: ci
    issuer: https://token.actions.githubusercontent.com
    audiences: [dns-gate]
roles:
  site-records:
    rules:
      - zones: [example.com]
        actions: [dns.read, dns.record.write]
        records: {hosts: ["@", www], types: [A, AAAA, CNAME]}
bindings:
  - role: site-records
    team: web        # owns every record it creates
    subjects:
      - issuer: ci
        claims: {sub: ["repo:example/website:ref:refs/heads/main"]}
protected:
  - zones: ["*"]
    hosts: ["@"]
    types: [NS, SOA, MX, CAA]

Base git · config.yaml

Issuers, zones, roles, bindings, protected records. Reviewed by pull request, and the only place that decides who may edit or approve the policy.

Managed web UI · store

Revisions on top of the base, with diff, impact analysis, approval by another approver, atomic activation and rollback. A fresh sign-in is required to change it, and a redeploy never erases it.

Delegated a pipeline stack

A stack that creates pipelines writes each one’s role and binding in the same apply, through the Terraform provider, within bounds set in the base file.

Discovery the whole account

Every zone of the provider accounts is listed read-only and can be brought under management from the UI, without a redeploy.

Callers

Every caller brings its own short-lived identity

Pipelines and people never hold a provider secret. The same roles and the same ownership apply to all of them.

OpenTofu and Terraform

The KamorionLabs/dnsgate provider talks to the gate REST API, for every DNS provider behind it, alias records included. Writes carry the expected content of each record set, and a zone can be exported as HCL with import blocks whose first plan is empty.

resource "dnsgate_record_set" "www" {
  zone   = "example.com"
  name   = "www"
  type   = "CNAME"
  ttl    = 3600
  values = ["site.example.net."]
}

resource "dnsgate_record_set" "apex" {
  zone = "example.com"
  name = "@"
  type = "A"

  alias {
    name    = "d111111abcdef8.cloudfront.net."
    zone_id = "Z2FDTNDATAQYW2"
  }
}

Existing EuroDNS clients

Third parties without OIDC, such as ACME clients, use gate-issued API keys: hashed, expiring, bound to a network, a team and a role, rotated and revoked through the API. certbot, acme.sh, lego and cert-manager solve DNS-01 challenges through the gate's httpreq and acme-dns endpoints, with no CNAME.

Run it

One container, one Helm chart

The gate is a single Go binary with its web UI built in. Validate a configuration before you ship it, run it locally against a test zone, then deploy the chart.

Locally

# provider credentials, held by the gate only
export EURODNS_APP_ID=...
export EURODNS_API_KEY=...
# Route53: the AWS credential chain (role, profile)

go run ./cmd/dns-gate -check -config config.yaml   # validate only
go run ./cmd/dns-gate -config config.yaml

On Kubernetes

helm install dns-gate \
  oci://ghcr.io/kamorionlabs/charts/dns-gate \
  -f values.yaml
